❌ Final

Fix details or refund. Never retry as is.

P-101 → AC01Account not found
P-102 → AC04Account closed
P-210 → BE01Name mismatch
P-300 → AM02Over the rail limit

🔁 Retryable

Status enquiry first; retry with the same idempotency key.

P-500 → TEMPORARYPartner timeout

🛡️ Hold

To Compliance. Never auto-retry or re-route.

P-777 → RR04Compliance hold

❓ Unknown

Treat as pending, query status, alert, map it.

Any new codeNot in the table

P-codes are invented examples; AC01, AC04, BE01, AM02 and RR04 are ISO 20022 external status reason codes.

    Failure handling

    Six things that break in production: how we spot each, and what we do.

    ⏳Timeout on create

    DetectNo response or a 5xx

    DoUnknown, not failed: query status; retry only with the same key

    🔀Repeated or out-of-order callbacks

    DetectSame event again, or an older status

    DoDedupe events, not payouts; a final status never goes backwards

    📈Rejection spike

    DetectOne reason code above its baseline

    DoRule out our own changes, then escalate with data

    ❓Unmapped error code

    DetectCode missing from the map

    DoHold as pending, query, alert, then map it

    ⏰Missed cutoff or holiday

    DetectBatch sent after the window

    DoShow the real credit date; never resend

    🛡️Compliance hold

    DetectHold status or RR04

    DoTo Compliance; never retry or re-route around it

    Rejection rate by reason code · US→PH InstaPay Illustrative
    This weekPrior 4 weeks
    ⚠️ AC01 is about 8× its baseline while the other codes are flat, so it points at one cause.
    -- Rejection rate by reason code: this week vs the prior 4 weeks (illustrative names)
WITH w AS (
  SELECT status, reason_code,
         created_at >= now() - interval '7 days' AS this_week
  FROM   payouts
  WHERE  partner_id = 'corvid' AND corridor = 'US-PH'
    AND  created_at >= now() - interval '35 days'
)
SELECT reason_code,
  round(100.0 * count(*) FILTER (WHERE this_week)
        / nullif((SELECT count(*) FROM w WHERE this_week), 0), 2)     AS pct_this_week,
  round(100.0 * count(*) FILTER (WHERE NOT this_week)
        / nullif((SELECT count(*) FROM w WHERE NOT this_week), 0), 2) AS pct_prior_4_weeks
FROM   w
WHERE  status = 'REJECTED'
GROUP BY reason_code
ORDER BY pct_this_week DESC;
